# shinkin

信用金庫の財務データ取得スクリプト。

## データソース

金融庁「中小・地域金融機関情報」（https://www.fsa.go.jp/policy/chusho/shihyou.html ）が
公開している信用金庫・信用組合の主要勘定一覧（Excel）を取得元とする。

取得できる項目（信用金庫ごと）:
- 都道府県、金融機関コード、金融機関名、法人番号、本店所在地、店舗数
- ディスクロージャー誌（Web）へのリンク
- 預金積金、貸出金（百万円）
- 自己資本比率、不良債権比率（%）
- 中小企業等向け貸出残高・貸出先件数（前年度/当年度）

## 使い方

```bash
pip install -r requirements.txt
python3 scripts/fetch_shinkin_financials.py --out data/shinkin_financials.csv
```

個別金庫のディスクロージャーPDF抽出でスキャン画像PDFのOCRフォールバックを
使う場合は、別途Tesseract本体(日本語言語データ込み)が必要:

```bash
apt-get install -y tesseract-ocr tesseract-ocr-jpn
```

(未インストールの場合はOCRを黙ってスキップし、通常のテキスト抽出のみ行う)

金融庁のファイルURLは年度更新のたびに変わる（例: `zenkoku/2025-2.xlsx`）。
最新のURLは https://www.fsa.go.jp/policy/chusho/shihyou.html の
「信用金庫・信用組合」欄のリンクから確認し、`--url` で指定する。

```bash
python3 scripts/fetch_shinkin_financials.py \
  --url https://www.fsa.go.jp/policy/chusho/shihyou/zenkoku/<年度>.xlsx \
  --out data/shinkin_financials.json
```

個別信用金庫のより詳細な財務データ（決算書全体）が必要な場合は、
出力される `disclosure_url` 列から各金庫のディスクロージャー誌（PDF）に
アクセスする。収益構造・業種別貸出金・有価証券ポートフォリオの取得については
下記を参照。

## 個別金庫の詳細データ（収益構造・業種別貸出金・有価証券ポートフォリオ）

FSAの集計Excelには含まれない、より詳細な項目
（収益構造＝損益計算書の内訳、貸出金の業種別内訳、有価証券の
種類別・残存期間別残高）は、各信用金庫が個別に公開する
ディスクロージャー資料（PDF）にのみ掲載されている。

これらのPDFはサイト構成・ファイル分割の仕方が金庫ごとに異なるため、
`scripts/extract_disclosure_pdf.py` はPDFのテキストからキーワード検索で
該当ページを特定し、行単位のラベル・数値マッチングで抽出する方式を取っている
（開示項目自体は信用金庫法施行規則等に基づく共通様式であり、業種区分も
日本標準産業分類の大分類に準じているため、金庫が変わってもラベルの
文言はほぼ共通という前提に基づく）。

### 使い方（単体）

```bash
python3 scripts/extract_disclosure_pdf.py \
  --url https://example.co.jp/disclosure/report.pdf \
  --out result.json

# PDFが複数ファイルに分割されている金庫の場合、順番に複数指定するとページを連結して処理する
python3 scripts/extract_disclosure_pdf.py \
  --url https://example.co.jp/disclosure/part1.pdf \
  --url https://example.co.jp/disclosure/part2.pdf \
  --out result.json
```

### パイロット実行（4金庫）

`scripts/pilot_institutions.json` に、規模の異なる4金庫
（栃木信用金庫・稚内信用金庫・城南信用金庫・伊達信用金庫）のPDF URLを
登録済み。まとめて実行する場合:

```bash
python3 scripts/run_disclosure_pilot.py
```

結果は `data/pilot/<金庫名>.json` に出力される（このリポジトリには
実行結果のサンプルをコミット済み）。

### PDFの自動発見（`scripts/discover_disclosure_pdf.py`）

金庫ごとにサイト構造が異なるため、FSAの一覧にある「ディスクロージャー(Web)」
リンク先のページから、最新のディスクロージャー資料PDFをキーワード
（計数編・資料編・財務データ・一括ダウンロード等）とページ内リンクの
1階層フォローでベストエフォート発見する。

```bash
python3 scripts/discover_disclosure_pdf.py "https://example.co.jp/disclosure/"
```

### 拡張バッチ実行（`scripts/run_disclosure_batch.py`）

FSAのExcelから対象金庫をサンプリングし、PDF自動発見・ダウンロード・
抽出までを一括実行する。

```bash
python3 scripts/run_disclosure_batch.py \
  --xlsx /path/to/zenkoku.xlsx \
  --sample-per-prefecture 1 \
  --out-dir data/sample_47
```

**47都道府県から1金庫ずつサンプリングした実行結果**（`data/sample_47/`に
コミット済み）:

| 指標 | 件数 |
|---|---|
| PDFの自動発見に成功 | 42/47 (89%) |
| 収益構造・業種別貸出金・有価証券ポートフォリオの3項目すべて取得 | 18/47 (38%) |
| 3項目のうち1つ以上取得 | 37/47 (79%) |
| 収益構造(損益の状況)を取得 | 33/42 |
| 業種別貸出金を取得 | 29/42 |
| 有価証券ポートフォリオを取得 | 23/42 |

### 全254金庫での実行結果

```bash
python3 scripts/run_disclosure_batch.py \
  --xlsx /path/to/zenkoku.xlsx \
  --sample-per-prefecture 999 \
  --out-dir data/all_254
```

信用金庫254金庫すべてに対して実行した結果（`data/all_254/`にコミット済み。
生PDFは`_raw_pdf/`配下にダウンロードされるがサイズが大きい(約2GB)ため
gitignore対象）:

| 指標 | 件数 |
|---|---|
| PDFの自動発見に成功 | 249/254 (98%) |
| 収益構造・業種別貸出金・有価証券ポートフォリオの3項目すべて取得 | 203/254 (80%) |
| 3項目のうち1つ以上取得 | 220/254 (87%) |
| PDFが発見できなかった | 4/254 |
| ダウンロード・解析エラー | 1/254 |

上記は5ラウンドのバグ修正・ヒューリスティック改善を経た数値で、
47金庫サンプル最初の実行（3項目達成38%）から着実に改善している。
バッチを複数回実行すると、同一サイトへの連続アクセスによる一時的な
ブロック(403等)で毎回違う金庫が数件失敗する再現性の低いノイズが
乗るため、この数値は複数回分の実行結果から金庫ごとに最良のものを
採用したマージ済みデータ。単純に1回の実行結果だけを見ると
ノイズで数件上下することがある。

これまでに直した主なバグ:
- 章立てが細かく分割されたPDFサイトで、前書き部分ではなく本当の
  財務データ巻を選ぶよう改善（北海道信用金庫等）
- 「開示項目一覧」という目次ページを実データと誤認する問題を修正
  （神戸信用金庫等）
- 日本語ファイル名PDFのURLエンコード漏れでダウンロードが
  失敗する問題を修正（大阪商工信用金庫等）
- Shift_JISページの文字コード誤判定でリンクテキストが文字化けし
  キーワード一致が機能しない問題を修正（いちい信用金庫等）
- 複数候補URLの一部が404の場合に全体を諦めていたのを、成功した分だけで
  進めるよう改善
- URLのクエリ文字列やファイル名中の日付が無関係な文書のスコアを
  不当に押し上げる問題を修正し、正誤表・経済レポート等を除外
  （日高信用金庫・福岡ひびき信用金庫等）
- 一覧ページ上の弱い候補（バンドルキーワードのみ一致、例:
  周年記念誌の「全ページ」）が見つかった時点で探索を打ち切り、
  サブページにリンクされた本当のディスクロージャー誌を見逃していた
  問題を修正（大分みらい信用金庫。ユーザーによる目視確認で発覚）
- ユーザーが「見つからない金庫にも必ずPDFがある」と指摘したことを
  受け、`pdf_not_found`だった22金庫を1金庫ずつリサーチエージェントで
  再調査し、discover側の以下を修正（詳細はコミット履歴参照）:
  metaリフレッシュ・`<base href>`・フレームセット・クロスドメイン
  リダイレクト・末尾スラッシュ依存・CMSのクエリ文字列型ダウンロード
  リンクへの未対応、共有ホスティングでのドメインルートへの誤った
  フォールバック、除外キーワード「iban」が金庫名「tachibana」に
  誤爆していた問題、空文字列連結時の末尾スペースでバンドル判定が
  効かないバグ、新しさスコアがキーワード一致にゲートされ最新の
  素っ気ない命名のファイルが古い「資料編」表記に負ける問題、
  半期版と通期本編の同点問題。22金庫中21金庫を修正し、1金庫
  （越前信用金庫）のみ環境固有のbotブロックにより対応不可。
- 続けて「PDFは見つかるが0/3」だった38金庫についても同様にリサーチ
  エージェントで再調査し、extract側に以下の汎用修正を実施:
  - 見出しを「経 常 収 益」のように1文字ずつ全角スペースで区切って
    組版するサイトへの対応（空白除去した版でも照合、昭和信用金庫等）
  - 見出し自体が図形化されテキストとして存在しないページでも、
    データ行のパターン一致だけで判定できるよう、見出しキーワードが
    見つからない場合は全ページを走査するフォールバックを追加
    （高知信用金庫等）
  - ページのmediabox外に置かれた「幽霊」文字（縦書きサイドバー見出しが
    非表示領域に重複配置されている）が本文行に混入する問題を、
    ページをmediabox内にcropすることで解消（奈良信用金庫等）
  - 「P2〜15」「P16〜21」のようにページ範囲で分割された章立てPDFで、
    決算表がどのファイルにあるか事前にわからないため、同点付近の
    ページ範囲ファイルを複数まとめて候補に含めるよう改善
    （福岡ひびき信用金庫・大阪シティ信用金庫等）
  - 損益の状況が5年間の主要指標サマリー（経常収益・業務純益・
    経常利益・当期純利益の4項目）のみのことがあるため、判定閾値を
    5→4行に緩和
  - ローマ字表記「shiryou/siryou」（資料編）がキーワード未登録で、
    同点の本編ファイルに負けていた問題を修正
  この結果、3項目達成が108/254(43%)→203/254(80%)に大きく改善した。

`data/all_254/`のデータと下記のカバレッジ一覧（金庫ごとの3項目達成
状況を検索・並べ替えできるダッシュボード）は随時再生成できる:
`scripts/run_disclosure_batch.py`実行後、`data/all_254/_summary.json`
を集計するだけ。

### 既知の制約

- PDFのレイアウトは金庫ごとに異なり、また同一金庫でも年度・半期/通期で
  フォーマットが変わることがあるため、本スクリプトはベストエフォート実装。
  抽出できなかった項目は `null` になる。
- 同一ページに複数の表（例: 保証・信用の集計表と業種別貸出金表）が
  含まれる場合、「合計」「小計」「その他」など共通ラベルの行が
  意図しない表からも抽出されることがある（`raw_line` を見て確認すること）。
- PDF自動発見・抽出の改善によっても解決できない、残り約2割の金庫は
  主に以下のパターン（`data/all_254/_summary.json` で判別可能）:
  1. **スキャン画像PDF / ページが1枚の画像として埋め込まれている**
     （テキストレイヤーが一切無く、OCRが必須）— 空知信用金庫・
     ひまわり信用金庫・但陽信用金庫等
  2. **文字がベクトルパス(アウトラインフォント)化されている**
     （画像ですらなく、ページをラスタライズしてOCRする必要がある）—
     会津信用金庫・奈良信用金庫の一部ページ等
  3. **ディスクロージャー資料がPDFとしてリンクされていない**サイト
     （FlippingBook等の埋め込みフリップブックビューアのみ）—
     中栄信用金庫・川之江信用金庫等。ページ単位のHTML(`pageindices/`
     等)からテキストを再構成すれば取得できる場合もあるが、サイト
     ごとの個別対応が必要
  4. **JavaScriptで動的にPDF一覧を取得するCMS**（佐賀信用金庫の
     Kuroco CMS等）— サイト固有のAPIエンドポイントを解析すれば
     取得できるが、汎用化しにくい
  5. **環境固有のbotブロック**（越前信用金庫、Akamai等）—
     スクレイピング手法を変えても解決しない
- 全254金庫規模では、上記のような未対応サイトが一定数（1〜2割）残る
  前提で、取得できた分（1項目以上: 220/254、87%）をデータセットとして
  使うのが現実的。3項目完全一致は203/254(80%)まで到達している。
